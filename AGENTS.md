# Руководство по работе с репозиторием

## Структура проекта

Репозиторий содержит русскоязычную базу знаний по Эргономичному подходу, публикуемую с помощью Hugo и Asciidoctor.

- `kb/`: статьи AsciiDoc в разделах `production-code/`, `testing/`, `process/`, `terminology/` и `additions/`; изображения хранятся рядом со статьями.
- `wiki/content/`: главная страница и страницы об авторе и сайте; Hugo подключает `kb/` по пути `/docs/`.
- `wiki/layouts/`, `wiki/assets/`, `wiki/static/`: шаблоны, SCSS и статические ресурсы.
- `wiki/scripts/`: проверка ссылок и тесты шорткодов.
- `wiki/themes/hugo-book/`: тема как подмодуль Git; для изменений предпочитайте переопределение шаблонов в `wiki/layouts/`.
- `.github/workflows/hugo.yaml`: сборка и публикация на GitHub Pages.
- `workbench/`: локальные рабочие материалы, исключённые из Git.

## Команды сборки, тестирования и разработки

Выполняйте команды из корня репозитория.
Используйте Hugo extended 0.167.0 (как в CI), Ruby, Asciidoctor, Rouge и Python 3; для тестов шорткодов установите pytest.

```bash
git submodule update --init --recursive
hugo server --source wiki --disableFastRender --renderToMemory
hugo --source wiki --minify
python3 wiki/scripts/check_wiki.py wiki/public
python3 -m pytest wiki/scripts/test_term_shortcode.py
```

Команды соответственно инициализируют тему, запускают предпросмотр с автообновлением, собирают сайт, проверяют ссылки, изображения и якоря в результате сборки и тестируют отображение терминов.
Не добавляйте в коммиты сгенерированные файлы из `wiki/public/` и `wiki/resources/_gen/`.

## Оформление материалов, стиль кода и именование

Пишите статьи на русском языке, сохраняя авторский смысл и стиль.
Используйте содержательные имена файлов в нижнем регистре с дефисами, расширение `.adoc` для статей и `_index.adoc` для индексных страниц разделов.
Сохраняйте метаданные YAML в начале файлов и используйте относительные ссылки `xref` между статьями.
Каждое предложение начинайте с новой строки; абзацы разделяйте пустыми строками.
Статьи терминов, используемые шорткодом `term`, должны содержать один непустой абзац между `// tag::definition[]` и `// end::definition[]`.
Следуйте оформлению соседнего кода: четыре пробела в Python, два — в SCSS и вложенных конструкциях шаблонов.
Общие для репозитория форматтер и линтер не настроены.

## Правила тестирования

После изменения материалов собирайте сайт и запускайте проверку ссылок.
При изменении шорткодов запускайте pytest; используйте файлы `test_*.py` и функции `test_*` с содержательными именами.
Тесты запускают Hugo на временных сайтах и проверяют успешное отображение и обработку некорректных определений.
Числовой порог покрытия тестами не установлен.
Проверяйте изменения вёрстки при настольной и мобильной ширине экрана.

## Правила коммитов и пул-реквестов

В истории преобладают краткие описания на русском, иногда с префиксами `docs:` или `build:`.
Объединяйте в коммит только связанные правки и описывайте конкретное изменение.
Отправка изменений в `master` запускает публикацию после сборки и проверки ссылок.
